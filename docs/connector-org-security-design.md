## Data model and trusted authority

Add nullable `organization_id UUID` to `connector_configurations` and `connector_run_history`. Historical NULL configurations and runs remain NULL; no guessed backfill or tenant adoption. New tenant writes derive org exclusively from the verified, freshly reloaded user identity (`_organizationId`) in auth middleware, not JWT-stored, body, query, header, or a tenant-selected id. The independent platform-admin marker must be re-read from a trusted user record on every token/API-key request and must not derive from a tenant role or org. No public route can set the marker; the seeded default admin lacks it. Platform admins may manage legacy NULL rows explicitly but must not accidentally expose legacy rows in tenant lists. Run insert derives the owning org from the parent configuration, never from the caller or a job argument. Database FK/check must prevent a non-NULL run org differing from its parent (including reassignment race). Existing NULL-org runs are only visible with the matching legacy config to platform admins. Name uniqueness remains globally enforced; collisions must not reveal foreign names.

## Read/write and response boundaries

All config id/name and run id reads, updates, deletes, tests, resources, metrics, histories, cancellations and triggers require the verified org at query time; foreign and missing ids use the same 404 shape before any mutation. Lists and aggregates are org-bound and exclude NULL for tenants. Platform-admin legacy access is narrow, explicit and not implicit global tenant bypass. REST, GraphQL, integration-hub, CLI and worker entry points require equivalent authority or must fail closed. A standalone unauthenticated connector service is not a trusted caller.

`connection` and nested secret-bearing configuration (`options`, `resource_configs`) are write-only. Public representations explicitly project non-secret fields, never return DB `*` or recursively redact arbitrary secret key spellings. Run `errors`, `error_message`, raw logs, job payloads and returnvalues are untrusted secret carriers: public responses use bounded safe status/count fields and coded errors; raw exception messages cannot cross HTTP/GraphQL or logger boundaries. Execution may read the scoped secret only inside the trusted executor. Legacy stored secrets get the same projection.

## Deployable consumers and privilege risks

* API server: REST configuration and run routes and GraphQL resolvers derive organization from the freshly reloaded `AuthService` user record; GraphQL secret fields are write-only. REST and GraphQL shared connector lifecycle mutations refuse **every** caller with a fixed error, including verified platform operators. The seeded default admin has no platform marker.
* Standalone integration-hub: `src/index.ts` applies independent fresh API-key/token verification and organization scope before mounting `connectorsRouter`. Hub responses project public config/run fields and fixed errors, not stored secrets or raw provider exceptions. Request-supplied organization, JWT org claim and an API-server assertion cannot grant authority.
* Worker/execution: the hub loads only enabled, `schedule_enabled=true`, credential-free, non-NULL-org schedules; it polls the database every 30 seconds to reconcile cross-process REST/GraphQL edits, including disable, delete, cron change and credential references. Each firing reloads the ID, owner, current schedule flag and exact cron expression before connector construction; the history insert checks them again. The timer can remain registered for up to 30 seconds after a change but cannot run a now-ineligible schedule. Package-root `IntegrationManager`/`getIntegrationManager`/`ConnectorConfigurationRow` and `ConnectorExecutor` exports are removed. Trusted API/hub consumers deep-import the manager; this is **not** an authorization boundary against code running in-process with database access. Do not load untrusted plugin/script code into the API or hub process.
* Clients: CLI and web UI use authenticated configuration/run routes; installed connector read aggregates require org predicates. The CLI installer and web installation wizard are removed; shared REST/GraphQL lifecycle routes return fixed unavailable errors. The REST run endpoint only queues history and is not an execution-success signal.
* Privilege/migration: global unique `connector_configurations.name` is a cross-tenant create-conflict oracle; changing it to org-keyed uniqueness also requires id-keyed manager registry/scheduling, and NULL uniqueness for legacy. `credential_id` references a globally keyed credential; execution denies reference-backed configs until independently proven credential ownership exists. Historical run `errors`, `error_message`, and `connector_run_log_entries.message` can already contain secrets: safe projection should omit them, not attempt ad-hoc redaction. DB integrity needs a parent/run org match enforced against concurrent reassignment. Deny all tenant NULL reads and runs; dedicated platform operator may explicitly initiate NULL legacy runs only after fresh identity validation, never through automatic startup cron. No public provisioning setter or trusted caller-owned flag; default seeded account must remain unprivileged.

Hub `/api/v1/transformation-rules` uses a separate authentication-and-denial router. Transformation rules and lookup tables are global tables without `organization_id`; until the dedicated HP1-S6/P-6 platform-admin flag merges, every caller (including unauthenticated users and authenticated tenants/platform operators) receives the identical fixed HTTP 403 `TRANSFORMATION_RULES_UNAVAILABLE` response before any SQL. No role, caller org or generic authentication grants this API. Founder ruling 2026-10-08 reserves eventual platform-admin-only access for a separately approved and reviewed follow-up; the in-process mapper and SQL tables remain unchanged.

`credentials` in the baseline schema has no organization_id, so a connector's `credential_id` alone does not prove credential ownership. Founder ruling 2026-10-07, Choice A: **all** execution, connection tests, and validation of stored credential references fail closed before any credential lookup/decrypt, including platform-admin and NULL legacy configurations. Return fixed, non-identifying `Connector credential reference unavailable` (REST/hub HTTP 409; GraphQL `CONNECTOR_CREDENTIAL_UNAVAILABLE`). This approved functional regression does not change the credentials table. Inline `connection` remains scoped and write-only. Re-enabling references requires a separate reviewed change after HP1 credential ownership is merged.

## API contract

Authenticate to the API server or standalone integration hub; a missing verified organization returns 403 unless the separately verified platform-admin marker is present. Configuration and run IDs or names belonging to another organization return the same 404 body as nonexistent IDs; lists and run aggregates exclude foreign and legacy rows. Request bodies, headers, and JWT organization claims cannot override the fresh verified user organization. `organization_id` is server-assigned on new configurations and run history.

REST `/api/v1/connector-configs` and standalone hub `/api/v1/connectors` accept inline `connection` and `options` on writes, but responses project only public identifiers, organization, type, enabled/schedule and timestamps. Resource configuration secret values, raw run `errors`, `error_message`, and run-log text are never public. To change a saved secret, supply a new value; the API cannot return the old value. A stored `credential_id` produces the fixed refusal above on test/run, before credential-table access and without creating a new run. Ordinary tenant `admin` users cannot read NULL-org historical rows. Hub name routes select the platform operator's own organization by default; append `?legacy=true` to explicitly select NULL-org history when names collide. Tenants cannot use that selector to reach legacy rows. Legacy NULL-org configurations do not auto-schedule.

Nonempty partial updates to write-only JSON objects merge supplied nested keys atomically with the saved value on REST, GraphQL and hub; omitted keys and nested empty objects (including saved secrets) remain unchanged. Explicitly supplied leaf values replace their prior value. Empty `connection`/`options` editors do not clear saved credentials, and REST `resource_configs: {}` clears the whole resource configuration. Installed connector templates expose only safe descriptors and configuration field definitions across REST, GraphQL and hub type routes, never stored template defaults or nested raw metadata. Registry/database errors and run resource IDs do not enter HTTP errors or logs verbatim. Shared installation, update, verification, uninstall and registry refresh refuse all API identities with a fixed unavailable error.

The connector execution logger uses fixed event messages and numeric counters only; caller-supplied connector names and resource identifiers are never logger payloads. In-process connector events retain their existing contract.

Founder signed Choice A deletes the installer implementation, package-root `ConnectorInstaller`/`getConnectorInstaller`/`DownloadOptions` exports, deep path, CLI install/update/uninstall/verify/repair tooling, and web installation controls. No in-repository application operator installer remains and no compatibility shim exists. External consumers must move package integrity verification and file placement to deployment tooling **outside** the application; this work authorizes no deployment or live packaging actions. No known in-repository production consumers of the removed installer existed.

The REST manual run endpoint currently inserts an organization-bound `queued` history row but has no in-repository worker consumer; its 202 means recorded, not executed. Hub/GraphQL manual runs invoke the organization-checking `IntegrationManager`. Do not treat REST queued status as an execution success signal.
