# R-CRED-2: connector ownership and write-only configuration

## Baseline and ordering

Migrations are numbered and additive. Existing connector ownership migration `018_connector_organization_scope.sql` and credential ownership migration `021_credential_organization_scope.sql` precede `022_connector_jsonb_merge.sql`. `runMigrations()` discovers entries by filename/checksum; do not modify previously applied migrations, `001`, or initdb.

## Data model and trusted authority

Add nullable `organization_id UUID` to `connector_configurations` and `connector_run_history`. Historical NULL configurations and runs remain NULL; no guessed backfill or tenant adoption. New tenant writes derive org exclusively from the verified, freshly reloaded user identity (`_organizationId`) in auth middleware, not JWT-stored, body, query, header, or a tenant-selected id. Until the dedicated HP1-S6/P-6 authority is available, no platform marker grants legacy connector authority: historical NULL-org configurations and runs are inaccessible to **every** caller. Run inserts derive the owning org from the parent configuration, never from caller input. The database guard prevents a run org from differing from its parent, including during reassignment. Names are tenant-local, with independent NULL legacy uniqueness.

## Read/write and response boundaries

All configuration and run reads, updates, deletes, tests, resources, metrics, histories, cancellations and triggers require the verified org at query time; foreign, NULL-org and missing IDs have the same 404 shape before mutation. Lists and aggregates exclude NULL for every caller, including a principal carrying a raw `_platformAdmin` marker. REST, GraphQL, integration-hub, CLI and worker entry points require equivalent authority or fail closed. A standalone unauthenticated connector service is not trusted.

`connection` and nested secret-bearing configuration (`options`, `resource_configs`) are write-only. Public representations explicitly project non-secret fields, never return DB `*` or recursively redact arbitrary secret key spellings. Run `errors`, `error_message`, raw logs, job payloads and returnvalues are untrusted secret carriers: public responses use bounded safe status/count fields and coded errors; raw exception messages cannot cross HTTP/GraphQL or logger boundaries. Execution may read the scoped secret only inside the trusted executor. Legacy stored secrets get the same projection.

## Deployable consumers and privilege risks

* API server: REST configuration and run routes and GraphQL resolvers derive organization from the freshly reloaded `AuthService` user record; GraphQL secret fields are write-only. REST and GraphQL shared connector lifecycle mutations refuse **every** caller with a fixed error, including verified platform operators. The seeded default admin has no platform marker.
* Standalone integration-hub: `src/index.ts` applies independent fresh API-key/token verification and organization scope before mounting `connectorsRouter`. Hub responses project public config/run fields and fixed errors, not stored secrets or raw provider exceptions. Request-supplied organization, JWT org claim and an API-server assertion cannot grant authority.
* Worker/execution: the hub loads only enabled, `schedule_enabled=true`, credential-free, non-NULL-org schedules; it polls the database every 30 seconds to reconcile cross-process REST/GraphQL edits, including disable, delete, cron change and credential references. Each firing reloads the ID, owner, current schedule flag and exact cron expression before connector construction; the history insert checks them again. The timer can remain registered for up to 30 seconds after a change but cannot run a now-ineligible schedule. Package-root `IntegrationManager`/`getIntegrationManager`/`ConnectorConfigurationRow` and `ConnectorExecutor` exports are removed. Trusted API/hub consumers deep-import the manager; this is **not** an authorization boundary against code running in-process with database access. Do not load untrusted plugin/script code into the API or hub process.
* Clients: CLI and web UI use authenticated configuration/run routes; installed connector read aggregates require org predicates. The CLI installer and web installation wizard are removed; shared REST/GraphQL lifecycle routes return fixed unavailable errors. The REST run endpoint only queues history and is not an execution-success signal.
* Privilege/migration: global unique `connector_configurations.name` is a cross-tenant create-conflict oracle; changing it to org-keyed uniqueness also requires id-keyed manager registry/scheduling, and NULL uniqueness for legacy. Migration `021_credential_organization_scope.sql` adds credential `organization_id`, but a globally keyed connector `credential_id` is not an independently verified connector-to-credential owner binding; execution denies reference-backed configs until that binding is reviewed. Historical run `errors`, `error_message`, and `connector_run_log_entries.message` can already contain secrets: safe projection should omit them, not attempt ad-hoc redaction. DB integrity needs a parent/run org match enforced against concurrent reassignment. Deny all tenant NULL reads and runs; dedicated platform operator may explicitly initiate NULL legacy runs only after fresh identity validation, never through automatic startup cron. No public provisioning setter or trusted caller-owned flag; default seeded account must remain unprivileged.

Hub `/api/v1/transformation-rules` uses a separate static-denial router. Transformation rules and lookup tables are global tables without `organization_id`; until the dedicated HP1-S6/P-6 platform-admin flag merges, every caller (including unauthenticated users and authenticated tenants/platform operators) receives the identical fixed HTTP 403 `TRANSFORMATION_RULES_UNAVAILABLE` before any authentication or SQL lookup. No role, caller org or generic authentication grants this API. Founder ruling 2026-10-08 reserves eventual platform-admin-only access for a separately approved and reviewed follow-up; the in-process mapper and SQL tables remain unchanged.
The hub mounts this denial before its global CORS, body parsers and authentication, so preflight OPTIONS, malformed JSON and valid credentials with an unavailable backing store get the same fixed 403; other hub routes retain their existing middleware order.

Migration `021_credential_organization_scope.sql` adds `credentials.organization_id` while leaving older credentials NULL; a connector's `credential_id` alone still does not prove access to that credential. Founder ruling 2026-10-07, Choice A: **all** execution, connection tests, and validation of stored credential references fail closed before any credential lookup/decrypt, including platform-admin and NULL legacy configurations. Return fixed, non-identifying `Connector credential reference unavailable` (REST/hub HTTP 409; GraphQL `CONNECTOR_CREDENTIAL_UNAVAILABLE`). This connector change does not modify the credentials table. Inline `connection` remains scoped and write-only. Re-enabling references requires a separately reviewed connector-to-credential ownership binding.

## API contract

Authenticate to the API server or standalone integration hub; a missing verified organization returns 403 even if a user record carries `_platformAdmin`. Configuration and run IDs or names outside the verified organization, including NULL-org history, return the same 404 body as nonexistent IDs; lists and aggregates exclude them. Request bodies, headers, query selectors and JWT organization claims cannot override the fresh verified user organization. `organization_id` is server-assigned on new configurations and run history.

REST `/api/v1/connector-configs` and standalone hub `/api/v1/connectors` accept inline `connection` and `options` on writes, but responses project only public identifiers, organization, type, enabled/schedule and timestamps. Resource configuration secrets, raw run errors and run-log text are never public. To change a saved secret, supply a new value; the API cannot return the old value. A stored `credential_id` produces the fixed refusal above on owned test/run before credential-table access and without creating a new run. No user, including a marker-bearing platform principal, can read or mutate NULL-org history; hub `?legacy=true` does not select legacy records.

Hub creation with a cron schedule defaults `schedule_enabled` to true unless explicitly disabled; edits may toggle `schedule_enabled` independently. Both web deployment wizards forward the Active toggle, schedule-enabled toggle and CronBuilder expression to the REST create endpoint, including disabled values. The hub reconciles persisted tenant-owned enabled schedules from that endpoint; inactive or schedule-disabled connectors do not register. Credential-backed and NULL-org configurations remain unschedulable.

Nonempty partial updates to write-only JSON objects merge supplied nested keys atomically with the saved value on REST, GraphQL and hub; omitted keys and nested empty objects remain unchanged. A root or nested JSON null/scalar becomes an object when patched with an object. Explicit leaf values replace their prior value. Empty `connection`/`options` editors do not clear saved credentials, while REST `resource_configs: {}` and GraphQL `resourceConfigs: {}` clear the whole resource configuration. Migration `022_connector_jsonb_merge.sql` supplies one atomic parameterized JSONB merge per field; connector writes bound the **combined** write-only JSON to 64 KiB, 256 keys, 256 nodes and depth 12, returning 400 / GraphQL `BAD_USER_INPUT` on excess. The API-server package exports the auth and connector helper subpaths used by the compiled hub, and its built entry is exercised without Jest aliases during image construction. Installed connector templates expose safe descriptors and field definitions, not saved template defaults or nested metadata. Registry/database errors and run resource IDs do not enter HTTP errors or logs verbatim. Shared installation, update, verification, uninstall and registry refresh refuse all API identities with a fixed unavailable error.

The connector execution logger uses fixed event messages and numeric counters only; caller-supplied connector names and resource identifiers are never logger payloads. In-process connector events retain their existing contract.

Founder signed Choice A deletes the installer implementation, package-root `ConnectorInstaller`/`getConnectorInstaller`/`DownloadOptions` exports, deep path, CLI install/update/uninstall/verify/repair tooling, and web installation controls. No in-repository application operator installer remains and no compatibility shim exists. External consumers must move package integrity verification and file placement to deployment tooling **outside** the application; this work authorizes no deployment or live packaging actions. No known in-repository production consumers of the removed installer existed.

The REST manual run endpoint currently inserts an organization-bound `queued` history row but has no in-repository worker consumer; its 202 means recorded, not executed. Hub/GraphQL manual runs invoke the organization-checking `IntegrationManager`. Do not treat REST queued status as an execution success signal.

The REST `POST /api/v1/connector-configs/:id/test` operation invokes the integration manager and can reach a provider. It requires connector `write` permission before the existing organization-owned config check; read-only viewers cannot trigger a connection test.

## Rollback and verification

Rollback is a code rollback only after stopping new writes and preserving org columns; dropping columns would destroy ownership and make new records legacy/ambiguous. Apply additive migrations `018` and `022` before serving the new API code; old code must not remain exposed during the transition. Isolated two-org PGlite regression checks identical NULL/foreign/missing not-found responses and no mutations for marked and ordinary users, own-org behavior, secret preservation, JSON merge boundaries and limits. Run compiled hub smoke, focused tests, exact-head CI, independent FULL native correctness and security reviews, an independent sensitive FULL operator pair, then obtain Nick's merge decision.
